# Studio conventions

This repo is a small animation and game studio. An agent authors scenes as code, renders them headless, and publishes a showcase to GitHub Pages. The owner directs and reviews.

## Toolchain

- Blender 4.5 LTS: `studio doctor` prints the path.
- Godot 4.7.2 standard: same.
- FFmpeg 9 with ffprobe.
- Python venv at `.venv` with Pillow, PyYAML, pytest.
- Node 24+ with pnpm 11 for `showcase/`.

Never commit `.venv`, `node_modules`, raw frames, Godot `.godot/`, or build output.

## Commands

```bash
./.venv/Scripts/python studio/studio.py doctor
./.venv/Scripts/python studio/studio.py validate
./.venv/Scripts/python studio/studio.py new 2d 004-my-study --title "My Study"
./.venv/Scripts/python studio/studio.py render 001-2d-bounce
./.venv/Scripts/python studio/studio.py export 003-micro-game
./.venv/Scripts/python studio/studio.py publish
./.venv/Scripts/python -m pytest studio/tests -v
cd showcase && pnpm typecheck && pnpm build
```

## Project anatomy

```
projects/<id>/
├─ project.yaml      manifest, the single source of truth
├─ render.py         Pillow renderer (type 2d)
├─ scene.py          Blender scene (type 3d)
├─ project.godot     Godot project (type game)
└─ README.md         what it is and how to reproduce it
```

Starter templates live in `studio/templates/{2d,3d,game}`. They use `__ID__` and `__TITLE__` placeholders that `studio new` substitutes. `studio/tests/test_templates.py` keeps them valid.

Manifest rules: id is `NNN-lowercase-name`, type is `2d | 3d | game`, engine must be `python | blender | godot` respectively. Resolution never exceeds 1920x1080. Outputs are repo-relative paths. Blender exports go to the declared `.glb` output.

## Media rules

- GIF under 8 MB, MP4/WebM under 20 MB, poster under 500 KB, GLB under 5 MB.
- `studio render` validates with ffprobe and refuses oversized output.
- Keep only curated output in `media/`. Raw frames live in `media/<id>/_frames/` and are ignored.
- A project needs `media/<id>/poster.jpg` before `studio publish` will include it.
- Long reels go to GitHub Releases, never git.

## Showcase data

`showcase/src/projects.generated.ts`, `showcase/public/media/`, `showcase/public/models/` and `showcase/public/builds/` are generated by `studio publish` and ignored by git. CI runs publish before every typecheck and build.

Game builds live under `builds/<id>/` so the `/play/<id>` route can fall back to the SPA shell instead of serving the game directory directly.

The site uses a `/animation-and-game-studio/` base path and ships route shells, `404.html` and `.nojekyll` so deep links resolve on Pages without a 404 status.

## Visual rules

- Light mode, warm cream backgrounds, ink text, one accent per scene.
- Restrained layout, but the landing hero should be distinctive.
- No em dashes in any copy.
- Respect `prefers-reduced-motion` on the site.

## Definition of done

1. Tests and `studio validate` pass.
2. Video output passes ffprobe checks at the declared resolution, fps and duration.
3. A still frame has been viewed and reads clearly.
4. `studio publish` has run and the site builds.
5. The deployed page has been opened in a real browser at desktop and mobile widths.
6. Commit in small conventional commits and push.
